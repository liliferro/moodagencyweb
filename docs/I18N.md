# Spanish and English editions

Spanish retains its existing URLs. English lives under /en/ with translated route names. Every one of the 47 Spanish HTML pages has an English counterpart, including the thank-you and error pages. The sitemap lists 90 indexable URLs.

## Editing and building

- src/en.json contains 2,016 reviewed source-to-English translations. They are editorial adaptations, not runtime machine translation.
- src/i18n-routes.json maps every Spanish page to its English counterpart.
- Install the pinned dependency: python -m pip install -r src/requirements-i18n.txt
- After editing Spanish HTML, run python src/build-bilingual.py. The existing src/build.py invokes this stage at the end as well.
- Missing translations stop the bilingual build before writing pages. Add translations for any new source text.
- Run python src/validate-i18n.py to check content structure, language links, internal links, metadata, JSON-LD, redirects and untranslated source strings.
- assets/site-en.js and assets/matdepot-case-en.js provide localized interactive behavior. When changing shared behavior, update both language versions.

## Locale behavior

The top ES/EN control links to the same page in the other language and preserves query parameters and section anchors. Navigation stays within the selected language. No automatic locale redirects or extra preference storage are used.

HubSpot uses the original form and CRM field values, with English labels, options, button, validation and confirmation. Its submission callback redirects to /en/thank-you/. No production lead was submitted during QA.

Historical client screenshots and original branded artwork remain intact; accompanying copy, captions, accessible descriptions and gallery controls are localized. Spanish search queries quoted as evidence retain their original wording, with an English explanation.
